# Experiments

## Исходный RAG baseline

`baseline.py` измеряет качество RAG на исходной, несжатой модели. Для каждого
примера HotpotQA поиск ограничен документами, связанными с его `example_id` в
`documents.json`. Эмбеддинги документов читаются из `documents.npy`, а сами
документы — из `documents.jsonl`.

По умолчанию из документов текущего примера выбираются 5 наиболее близких к
вопросу. Это число можно изменить через `--top-k`. Ответ генерируется
`Qwen3-8B` без сжатия KV cache. В итогах сохраняются answer EM/F1 и метрики
поиска Recall@k, Precision@k и доля примеров, для которых найдены все
supporting documents.

Перед запуском нужно завершить первичную подготовку данных и вручную установить
`constants.is_first_run = false` в `configs/config.toml`.

Из корня проекта:

```powershell
python -m experiments.baseline
```

Для короткого запуска на первых 10 примерах:

```powershell
python -m experiments.baseline --limit 10
```

Результаты каждого запуска сохраняются в отдельной папке
`experiments/results/baseline_<UTC timestamp>/`: `predictions.jsonl` содержит
метрики и найденные документы для каждого примера, `summary.json` — агрегаты,
параметры моделей и сведения о запуске.

## TT KV-cache baseline

`baseline_tt.py` повторяет тот же retrieval и generation протокол, но передает
модели собственный `TTCompressedCache`. Prompt-cache раскладывается библиотекой
`ttpy` в TT-ядра. Новые токены собираются в плотный хвост и раскладываются
отдельными блоками; attention получает восстановленные плотные K/V. Поэтому
число декомпозиций не растет с каждым токеном, а плотным остается только
незаполненный блок. TT-ядра и этот хвост хранятся на CPU; перед attention
плотные K/V переносятся на устройство модели.

Запуск:

```powershell
python -m experiments.baseline_tt
```

Параметры TT можно менять: `--tt-epsilon` задает относительную точность
TT-SVD (по умолчанию `0.01`), `--tt-block-size` — число новых токенов в блоке
(по умолчанию `16`). Остальные параметры, включая `--top-k`, `--limit`,
`--max-new-tokens` и `--seed`, имеют те же значения, что и в исходном baseline.

В дополнение к EM/F1 и retrieval метрикам отчет содержит размер плотного cache,
размер TT-ядер и плотного хвоста, отношение размеров, ошибку восстановления,
максимальный TT-rank и время TT-декомпозиции/восстановления. Размеры учитывают
payload тензоров и TT-ядер; накладные расходы объектов Python не входят.
Отношение размеров относится к сохраненному payload: оно не означает такое же
снижение пикового расхода памяти устройства, поскольку для attention плотные
K/V восстанавливаются на устройстве модели.

Каждый запуск сохраняет графики в папке `plots/` рядом с `summary.json`:
`quality_metrics.png` показывает answer и retrieval метрики,
`generation_metrics.png` — задержку, throughput и пиковую CUDA-память.
В TT-эксперименте также сохраняется `tt_cache_metrics.png` с размером cache,
compression ratio, ошибкой восстановления, TT-rank и временем обработки.
Пути к графикам добавляются в секцию `artifacts` файла `summary.json`.
